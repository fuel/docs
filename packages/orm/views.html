View support

You can also use the ORM to query database views instead of tables.

Two different ways of accessing views are supported:

  • A model representation of a single view
  • A model representation of a table with views for subsets

View model

A view model is simply a model that uses a view instead of a table for selection.
The resulting model objects will be read-only, any attempt to call save() or update() will return false. 

class Model_Patient extends \Orm\Model

	/**
	 * @var  string  define the name of the view this model should use
	 *
	 * @var string
	 */
	protected static $_table_name = 'vw_PatientView';

	/**
	 * @var  bool  the given table name is actually a view
	 */
	protected static $_table_is_view = true;

}

And that is it. Define the rest of the model as usual, and use is as a standard model:

// get the patient record for John Doe
$patient = Model_Patient::query()->where('name', '=', 'John Doe')->get_one();

// will return false, not throw an error !
$patient->save();

Note that for models, it is required to define a primary key, which by default is 'id'. If your view does not have an 'id' column, make sure the view has one or more fields which can be defined as primary key.

Table model with views

This is a standard ORM model, with the addition that you can define views to return table data. This can be useful in organisations where views are used by the database administrator to hide the selection SQL from the application developers. 

class Model_Patient extends \Orm\Model

	/**
	 * @var  string  define the name of the view this model should use
	 *
	 * @var string
	 */
	protected static $_table_name = 'Patients';

	/**
	 * @var  bool  define the available views on this table
	 */
	protected static $_views = array(
		// use the alias 'discharged' for the view 'vw_PatientsDischargedToday'
		// view returns all columns defined in the model properties
		'discharged' => array(
			'view' => 'vw_PatientsDischargedToday',
			'columns' => true,
		),
		// use the view name directly
		// and returns a specific set of columns
		'vw_PatientsAdmittedToday'  => array(
			'columns' => array(
				'id',
				'name',
				'dob',
				'room',
			),
		),
	);
}

You can now query the model the usual way, or define you want to use one of the views:

// check if John Doe was discharged today
$patient = Model_Patient::query()->use_view('discharged')->where('name', '=', 'John Doe')->get_one();

if ($patient)
{
	// yes, John Doe is discharged today
}

// check if John Doe was admitted today
$patient = Model_Patient::query()->use_view('vw_PatientsAdmittedToday')->where('name', '=', 'John Doe')->get_one();

if ($patient)
{
	// yes, John Doe is admitted today
	// note the patient object will contain a subset of data due to the column list defined
}
